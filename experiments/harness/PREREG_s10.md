# 阶段 10 预注册：非 Claude 生成模型（2026-10-21，写于任何阶段 10 生成调用之前）

## 目的
目前所有生成模型、judge 和先验面板都是 Claude。本阶段用 GPT（gpt-6-astra，经 Codex CLI 调用，reasoning medium，只读沙箱、空目录）作为生成模型，在两个公开空间上重复：
- **A**：judge 优化导致精度崩塌；
- **M**：先测量再提出能提高 SV。

## 设计（与阶段 5 和阶段 9 完全相同，只换生成模型）

**NB201**
- 运行编号 rep 116–139，每臂 24 次。
- 3 个臂：
  1. **BASE**：直接生成；
  2. **J**：阶段 2 在 NB201 上进化出的 judge harness，原样使用，由 Sonnet 训练；
  3. **A-100**：主动设计 100 个探针，测量方式与阶段 5 相同。

**HPOBench MLP**
- 运行编号 rep 200–223，每臂 24 次。
- 臂设计同上；测量用真实的单种子 test 差值，与阶段 9 相同。

**评分**
- BASE 和 J 由 Opus judge 打分，与之前所有阶段相同。
- **先验**：留一先验在排除生成模型后取面板均值。GPT 不在 Haiku/Sonnet/Opus 面板里，所以它的先验就是整个 Claude 面板的均值。这也意味着 SV 是相对于另一家厂商模型的共享先验来衡量的。
- 面板保持不变，以保证与之前各阶段可比。

## 判据（每个空间分别判定，与阶段 9 的代码相同）
- **M**：
  - 支持：A-100 的 SV 高于 BASE，单侧置换检验，与 A-SV 一起做 Holm 校正，p < .05，且精度 ≥ 0.8 × BASE；
  - 否定：差值的 90% CI 上界 < 0.5；
  - 其余：inconclusive。
- **A-prec**：
  - 支持：J 的精度比 BASE 低至少 0.2，且 p < .05；
  - 否定：精度差 > −0.1；
  - 其余：inconclusive。
- **A-judge**：
  - 支持：J 的 judge 分高于 BASE，p < .05；
  - 否定：J ≤ BASE；
  - 其余：inconclusive。
- **A-SV**：
  - 支持：J 的 SV 低于 BASE，Holm 校正后 p < .05；
  - 否定：J ≥ BASE；
  - 其余：inconclusive。

## 预期（事先写下，用于事后对照）
- A-prec 和 A-judge 在两个空间都复现。J harness 的规则（禁止常真的主张类型）与模型无关。
- M 在 HPOBench 上成立。NB201 上不确定，因为 GPT 对 NB201 的先验可能也很强（参照 Sonnet × NB201 的失败）。
- 论文主张如何随结果改写：
  - **A 在 GPT 上不成立**：论文的 A 只能写成"Claude 生成模型"；
  - **M 在 GPT 的两个空间都不成立**：M 写成"模型依赖"，并作为一项独立的发现报告。

## 描述性附加：GPT 的先验（不进入任何判据）
- 让 GPT 对 NB201 的 870 个格子和 HPOBench 的 148 个格子打先验分，共 34 次调用。
- 报告三项：GPT 先验与 Claude 面板均值的相关、GPT 先验与真值的相关、面板先验与真值的相关。这用来检验"共享先验"是否跨厂商成立。
- 这些文件存成留一面板不会读取的文件名（`out/xprior_gpt_*`、`out2/fcprior_gpt_*`），所以之前各阶段的 SV 数值不受影响。

## 替代解释
- **Codex CLI 是 agent 外壳**，带系统 prompt、在只读沙箱里运行。为避免它读取任何文件，调用都在空目录里进行。它的行为可能与直接调用 API 不同；这一点会写进局限。
- **J harness 是 Sonnet 训练的**：对 GPT 而言是跨模型迁移，与 Opus 在阶段 5 的情形相同。
