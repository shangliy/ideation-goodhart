# 阶段 1 预注册：ideation harness 的结构旋钮筛查（2026-10-20，写于任何生成调用之前）

目的：在训练空间 NAS-Bench-201 上，用部分因子设计找出哪些结构旋钮影响"为真且低先验"（SV）。同时检验 LLM judge 分数和 SV 是否相关，这是阶段 2"Goodhart"主线的前提。

## 训练空间（nb_space.py，CPU，已确定）
- 数据：NAS-Bench-201 的表格化结果（派生统计见 nb_space.json）；15625 个 cell，3 个数据集（C10、C100、IN16）。
- 主张形式："把边 j 设为算子 b，在父 cell 的边 k 为算子 c 时效果更高（或更低）"。
  - 共 870 个格子，1740 条有方向的主张；
  - 每个格子条件两边各至少 100 个父 cell。
- **判真**：3 个数据集的差值同号，且最小 |差值| ≥ 2.0 个百分点。
  - 有 198 个格子满足，即 198 条为真主张，占 1740 条的 11.4%，这也是随机抽样的精度；
  - 阈值在看到任何生成结果之前写定。
- **先验**：haiku、sonnet、opus 各自对 870 个格子给出 P(更高)，每次调用 30 个格子；P(更低) = 100 − P(更高)。约 87 次调用。
- SV = 为真，且留一先验 < 50。

## Harness 形态（本阶段只改结构，文本固定）
- 由 Python 编排，每个角色是一次 claude CLI 调用。
- 检索走 `search.py`：带屏蔽名单，按查询缓存，并记录日志。
  - 流程：角色先输出查询，Python 执行检索，再把结果交给角色写下一步。
- 输出契约固定：10 条结构化主张。

| 旋钮 | 0 | 1 | 2 |
|---|---|---|---|
| R 检索 | 无 | 同领域（NAS / 架构） | 跨领域（≥ 3 个非 ML 领域） |
| G 角色 | 单 agent | gap finder + innovator | gap finder + innovator + critic |
| C 挑战 | 无 | 找漏洞后修改 | 假设取反 |
| S 选择 | 直接产出 10 条 | 产出 30 条，由生成者按"最可能为真"选 10 条 | 产出 30 条，由生成者按"其他模型不太会想到、但可能为真"选 10 条（先验规避） |

- 设计：L9 正交表，4 个三水平因子，9 个配置；配置 1 是全 0，也就是直接生成。
- 每个配置独立跑 8 次，生成模型是 Sonnet。

## 指标（每次运行）
- SV 数、精度、平均留一先验、菜单外比例、token 成本（CLI 返回的 usage）。
- LLM judge 分数：opus 对这一组 10 条主张打"新颖度"和"质量"（1–10 分），不提供任何数据。

## 判据
- **K1 旋钮效应**：对 72 次运行的 SV 数做主效应分析，每个因子 3 个水平。
  - 支持：至少一个因子的主效应置换检验 p < 0.05，且最好水平比最差水平平均多 ≥ 1 条 SV / 次运行。
  - 否定：所有因子 p > 0.2。
  - 其余：inconclusive。
  - 预先写下的方向预测：R2 > R0；C1 ≈ C0（对应 P3 的 H1）；S2 的 SV 高于 S0、但精度低于 S0。
- **K2 judge 和 SV 是否相关**（阶段 2 的前提）：72 次运行上，judge 新颖度和 SV 数的 Spearman ρ。
  - ρ ≤ 0.2：前提成立，judge 不能代表 SV。
  - ρ ≥ 0.5：judge 是不错的代理，阶段 2 的 Goodhart 主线需要重新考虑。
  - 其余：inconclusive。
  - 同时报告 judge 新颖度和平均先验之间的相关。
- **K3 算力归一化**：按 SV / 1k token 重新排序。如果排在最前的配置变了，两种排序都报告。

## 替代解释和对照
- **检索泄漏**：
  - 屏蔽名单只看标题和摘要，摘要里不提 NB201、正文里用到它的论文会漏过；
  - 模型的参数知识本身也知道 NB201。
  - 所以 NB201 只作为训练空间，结论以阶段 2 的私有 CTR 空间为准。
  - 日志会报告每次运行的查询和被屏蔽的条数。
- **多花 token 就多出 SV**：用 K3 的成本归一化对照。
- **judge 偏向自己生成的风格**：judge 用 opus，生成用 sonnet，两者不同。
- **文献检索结果随时间变化**：按查询缓存，重复查询不会得到不同结果。
